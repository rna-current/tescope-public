TEscope User Guide

Complete guide to TEscope 0.2.0. Three parts, in reading order:

  1. Quick start (below) — first analysis in five minutes.
  2. Complete control reference — every menu item, button, field, checkbox, combo choice, mouse gesture, and status message of the GUI, screen by screen, with defaults and effects. Nothing in the app is undocumented.
  3. Interpretation concepts — what TEscope does vs what your upstream pipeline does; raw values vs display transforms; SEM vs copy-distribution bands; missing vs zero; NH/MAPQ limits; compatibility vs identity; coordinates; offline behavior and font portability.

A single-file build of the whole guide (cover + all three parts) is generated by assets/build_guide.py → TEscope_User_Guide.html / TEscope_User_Guide.pdf (see Building the distributable guide).

Quick start

Install

pip install tescope        # from the wheel / sdist
tescope --help             # CLI present
tescope gui                # desktop app

Or use a packaged build (no Python needed): Windows setup.exe or portable zip, macOS .app zip (right-click ▸ Open once — unsigned), Linux tar.gz (glibc ≥ 2.39). Details: docs/installation.md.

First analysis (GUI)

  1. Reference genome — pick your assembly (e.g. hg38) and press Download annotation once (network; a one-time per-assembly download). Or Import custom… with your own RepeatMasker .out.
  2. Transposable element — type a name in the search box (e.g. L1HS) and select the subfamily leaf in the tree.
  3. TE copy filters — optional; the live counter shows exactly how many copies the next run will use.
  4. Signal tracks — Add… (or drag & drop) your bigWig / bedGraph / BED / narrowPeak / BAM files. Give replicates the same Group to plot their mean ± SEM as one series.
  5. Press Run analysis. The Profile tab shows signal on consensus coordinates with a per-bin copy-support panel; Heatmap shows per-copy signal; QC records every decision the run made.
  6. File ▸ Save project… writes one YAML that reproduces everything — in the GUI (Open project…) or headless:
tescope run analysis.yaml --out results/

A fully offline synthetic walk-through (data + three configs + expected outputs + verifier) ships as the acceptance pack (tescope-acceptance-pack-<ver>.tar.gz, see its QUICKSTART.md).

Where to go next

  • Comparing full-length vs truncated copies → View: fragments (reference §9) and docs/filtering.md.
  • Unique vs multi-mapping reads (BAM) → the Mapping column (reference §7) and concepts.
  • Publication figures → Style… presets publication / publication_minimal (reference §14, docs/plot-style.md) and Export figure… (SVG/PDF + provenance sidecar).
  • Sequence & feature layer (Dfam or your own library) → reference §§5–6 and docs/sequence-browser.md.
  • Individual loci, subset comparison, upstream estimates, and TE feature files → the Loci tab and Locus Inspector (reference §§11–12) and docs/feature-import.md.

TEscope User Guide — complete control reference

Documented version: TEscope 0.2.0 (verified on the 0.2.0rc2 candidate; 0.2.0 differs from it only in the version string and the repository URL; every behavior below was verified against the application code and the running GUI of this version; nothing is inferred from a control's name). Coordinates in every on-screen readout are 1-based inclusive; the single exception is the user-feature table, which is 0-based half-open and labeled as such. "Analysis" in the Effect column means the setting is only read when you press Run analysis (and by Save project…); "Display" means it takes effect immediately.

1. Main window

  • Title bar: TEscope <version>; window/taskbar icon = profile-lens symbol. Default size 1280×820; drag the splitter between the left column and the results to resize (sidebar minimum 400 px; the sidebar scrolls vertically when panels don't fit).
  • Header strip: logo, TEscope, subtitle Transposable Element Consensus Profiling, version at the right.
  • Drag & drop anywhere on the window: local signal files are added as tracks; each unsupported file shows an "Unsupported file" warning naming the exact problem.
  • Status bar (bottom): the message starts as Ready and is color- tinted — accent while running, green on success (L1HS: 1,661/1,661 copies analyzed), amber when the run produced notes (… — 2 note(s), see QC tab), red on error. A slim progress bar appears on the right during downloads and analyses.

8. Run analysis

The accent-colored button under the sidebar. It first validates the whole setup — problems open "Cannot run" with the precise message (missing assembly/repeat/tracks, duplicate names, invalid mapping request, bad user-feature row, missing sequence file, invalid style value, annotation not downloaded). The run executes on a worker thread with live progress; on success the status bar reports {repeat}: {selected:,}/{annotated:,} copies analyzed (+ a note count pointing at the QC tab when applicable); on failure the error opens in "Analysis failed" (internal errors include a short traceback). The button is disabled only while a run is in flight; repeated runs replace the previous result cleanly.

16. Offline use and networking

Network is used only for: assembly annotation download (once per assembly), and Dfam feature/sequence lookups you request. Everything else — including previously downloaded references and caches — works offline. Your signal data never leave the machine.

TEscope User Guide — interpretation concepts

Short, explicit statements of what TEscope does and does not do. These matter for correct scientific reading of every figure.

Upstream responsibilities vs TEscope's

TEscope never aligns reads, calls peaks, normalizes libraries, or computes IP/input ratios. You bring processed signal (bigWig/bedGraph values, BED/narrowPeak intervals, aligned BAM/CRAM); whatever normalization those files carry (or lack) flows through unchanged. Comparing two libraries' amplitudes is only meaningful if YOU made them comparable upstream (e.g. depth normalization). TEscope's job: project each TE copy's genomic interval onto the repeat-consensus axis (per-RepeatMasker-hit affine mapping, strand-aware), aggregate across copies, and show honest denominators.

Raw values vs display transforms

The canonical per-bin values (per-copy means aggregated across copies) are computed once per run and never modified by any style, smoothing, normalization-display, zoom, or theme option — this is pinned by regression tests. Smoothing and the Normalize: combo change the DRAWN curve only; Export data… always includes the raw tables (and labels smoothed companions separately with their parameters).

SEM band vs copy-distribution bands

  • SEM = standard error of the plotted mean (between replicates for grouped series): how well the mean is estimated.
  • IQR / 10–90% ribbons = variation ACROSS TE COPIES: how much individual copies differ. Available only for ungrouped continuous tracks (needs the per-copy matrix). These are different quantities; neither is a parametric confidence interval, and TEscope deliberately does not offer one (typical inputs have n≤2 replicates, where a CI would imply unsupported precision). TE copies are genomic repeats, not independent biological replicates — never read a copy ribbon as replicate confidence.

Missing signal vs zero, and copy support

For bigWig/bedGraph, positions without data are MISSING (excluded from means — never treated as zero). For BAM coverage, zero reads IS a measured zero. Each profile row carries n_elements (copies whose genomic span covers the bin) and n_observations (copies that contributed a finite value): the denominators change along the consensus because truncated copies simply do not have 5′ positions. Bins supported by a handful of copies are noisy — always read profiles together with the support panel (the fragments view shows both per subset).

Mapping classes (NH/MAPQ) and their limits

Young-TE reads multimap by nature; the aligner upstream already chose primary placements. TEscope's unique/multi views make the observation set explicit — unique (NH=1), multi (NH>1), or unique (MAPQ≥t) — but cannot recover true read origins, and the semantics depend on the aligner that wrote the tags. multi requires NH (MAPQ cannot positively identify multi-mappers). Multi-mapping reads are counted once, at their primary position; secondary/supplementary records are never counted.

Compatibility vs identity (sequence & features)

Dfam or user sequences/features are shown only when the source's name/alias matches AND its length equals the analysis' consensus model exactly. That gate prevents coordinate nonsense, but a name+length match is NOT independent proof of base-level identity — provenance (accession, release, checksum) is recorded so you can verify. Incompatible sources are withheld with the reason shown, not stretched to fit. User-supplied libraries are read locally in place; their licenses remain the user's responsibility, and TEscope never bundles or redistributes repeat libraries.

Coordinates

Internally 0-based half-open; every user-facing readout (cursor, Go-to, search hits, FASTA headers) is 1-based inclusive. The one 0-based input is the user-feature table (labeled in the panel). The consensus axis is the RepeatMasker model implied by your annotation — coordinates on a different consensus model (other releases, other databases) can be offset; compare positions across studies as distances with that caveat, not as identities.

Offline behavior and SVG font portability

After the one-time annotation download (and any Dfam lookups you request), TEscope runs fully offline from its caches. Exported PDFs embed the resolved font (genuine Arial where installed, else Liberation Sans). Exported SVGs keep text as editable text declaring the Arial-first family chain, so another machine renders them with its own best match — pixel-identical cross-machine appearance is not guaranteed; use PDF when that matters.

Loci, subsets, and upstream estimates (0.2.0)

A "locus" row is one RepeatMasker annotation record. TEscope never merges records; the rm_id fragment linkage is displayed so you can see which records RepeatMasker attributes to one insertion. A row is therefore not asserted to be a complete biological insertion.

Selection is not analysis. Browsing, sorting, highlighting, and selecting loci change nothing. Only the explicit "Analyze selected loci"/"Compare with eligible" actions compute a subset aggregate — recomputed from the original per-copy values with the same aggregation as the main profile. The eligible population's aggregate is never modified, and both denominators stay visible. Subsets you select interactively are exploratory; TEscope deliberately runs no automatic significance test on them, because an interactively chosen subset is not an independent confirmatory finding.

Upstream per-locus estimates are table context, not signal. A count or model estimate per locus (e.g. Telescope's final_count) has no positional resolution: TEscope will sort and compare loci by it, but never spreads it along the consensus or draws it as a curve. Declared semantics are enforced: a total that includes unique evidence is never added to its unique component; a missing component is unavailable, not zero; native scores keep their tool-specific meaning (no cross-tool confidence score); and a selected subset never triggers re-estimation or reassignment. Estimates from an RNA-seq quantifier describe expression evidence under that tool's model and assumptions — they are not chromatin signal and are labeled with their assay.

Feature projection is bounded by the mapping that exists. The RepeatMasker .out format retains hit endpoints, not per-base alignments, so consensus→locus projection is affine within each hit: good enough to show where a feature falls on a copy, not to claim base accuracy. Features outside a copy's footprint get "no verified correspondence" rather than a stretched interval, and partial overlaps are flagged. Projection never proves an intact ORF or an active element; absence from a user-supplied annotation file is absence from that file, not biological absence.

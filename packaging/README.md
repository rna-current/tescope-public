# TEscope packaging

Goal: ordinary users install TEscope **without** Python, conda, samtools or
bedtools. Bioinformaticians keep using `pip`/`uv`/`pipx`.

## Deliverables

| Platform | Deliverable | Status |
|---|---|---|
| Windows | PyInstaller one-dir bundle → Inno Setup installer (`tescope.iss`) | built by CI on every version tag; installer executed silently and the installed app started in CI; unsigned |
| macOS | PyInstaller `TEscope.app` (arm64 on `macos-latest`) | built and start-tested (offscreen) by CI on every version tag; ad-hoc signature, not notarized |
| Linux (CLI/HPC) | `pip install tescope` / `pipx install tescope` / `uv tool install tescope` | wheel builds + installs, verified |
| Linux (GUI) | PyInstaller bundle | built by CI and started under Xvfb with the real xcb platform; also built natively on Rocky Linux 10 |

Bundles include `THIRD-PARTY-NOTICES.txt` (generated by `collect_licenses.py`
from the frozen environment — covers the PySide6/Qt LGPL-3.0 notice
obligation). The PyInstaller bootloader is GPL-2.0-with-bootloader-exception,
which permits MIT distribution of the frozen app.

## How to build locally

```bash
uv sync --extra gui
uv pip install pyinstaller
cd packaging
uv run pyinstaller --noconfirm tescope-gui.spec
# result: dist/TEscope/ (or dist/TEscope.app on macOS)
```

CI: `.github/workflows/package-apps.yml` builds unsigned bundles for all
three OSes on tag push or manual dispatch.

## Linux distribution strategy (explicit)

- **Primary channel: wheels/source** (`pip/pipx/uv tool install tescope`)
  — broad Linux compatibility via manylinux dependency wheels.
- **Prebuilt Linux bundle: convenience artifact only**, for distributions
  with glibc **>= the build host's glibc**. CI builds on ubuntu-latest
  (24.04, glibc 2.39): compatible in principle with Ubuntu 24.04+,
  RHEL/Rocky **10**+ (glibc 2.39), Fedora 40+; **not** RHEL/Rocky 9
  (2.34) or Ubuntu 22.04 (2.35). PyInstaller Linux binaries are not
  universally portable — never claim a "universal Linux binary".
- A native Rocky 10.1 build was validated end-to-end on a real X11
  display (2026-08-31).

**Linux build-host requirement (R-002):** the Qt xcb helper libraries
(libxcb-cursor, libxkbcommon-x11, xcb-util-{wm,image,keysyms,renderutil})
must be visible to the build so PyInstaller vendors them into
`_internal/` — otherwise the bundle cannot start on X11 hosts that lack
them, and injecting them at runtime via LD_LIBRARY_PATH segfaults (mixes
system libxcb with the PySide6-vendored copy). CI installs them via apt;
on Rocky build hosts:
`LD_LIBRARY_PATH=<dir with the xcb helper libs> pyinstaller …`.
The packaging workflow asserts the vendored libs and smokes the Linux
bundle under xvfb with the real xcb platform.

## Design notes

- The GUI bundle embeds the full analysis core; the desktop app never
  shells out to external bioinformatics tools.
- bigWig reading in bundles uses **pybigtools** (pure wheels on every OS);
  pyBigWig is bundled when available (Linux/macOS).
- BAM/CRAM support (pysam) is POSIX-only; the Windows bundle ships without
  it and the GUI explains this when a BAM is dropped.
- PySide6 is LGPLv3: we link dynamically (default for PyInstaller
  one-dir bundles) and ship the Qt license texts — do not switch to
  static linking without a license review.

## Remaining release-phase work

1. Windows: Inno Setup script (`.iss`), file associations for `.tescope.yaml`
   (optional), code-signing certificate.
2. macOS: Developer ID signing + notarization (`xcrun notarytool`).
   Primary target is Apple Silicon (arm64, `macos-latest`); Intel is NOT
   promised — an x86_64 build would need `macos-13` runners and separate
   validation.
3. Real-device GUI validation on Windows 10/11 and macOS — CI only proves
   the bundle builds and imports, not usability (see docs/limitations.md).
4. Bundle size: 374 MB unpacked on Linux (PySide6 119 MB — libicudata alone
   31 MB — pysam 51 MB). Python-module excludes for unused Qt are in the
   spec; the PySide6 hook still collects some unused Qt shared libraries
   (QtQuick/QtQml/QtPdf ≈ 20 MB) — binary-level filtering is a post-v0.1
   optimization, deliberately not done to avoid breaking plugin deps.
